# Project: Yohaku（余白）

**A Quiet Place Between Words and Sound.**

*在文字与声音之间，留一处属于自己的空白。*

## 一、项目愿景

开发一款融合文学阅读、漫画阅读、私人音乐收藏与环境声音的跨平台应用，名为 **Yohaku（余白）**。

Yohaku 不应该只是阅读器与音乐播放器的简单组合，而应该是一件具有文学气息、浪漫主义、日式物哀美学与艺术收藏感的软件作品。

软件的核心视觉概念是：

**一间属于用户自己的日式私人暗房。**

这间暗房收藏着用户珍爱的一切：

- 书籍是用木夹悬挂在细绳上的老照片。
- 音乐是木质留声机与唱片柜中的黑胶唱片。
- 阅读记忆保存在一卷卷旧胶片之中。
- 窗外有雨、夕阳、樱花和四季变化。
- 房间里偶尔有萤火虫飞舞。
- 玻璃风铃挂在窗边，微风吹过时轻轻作响。
- 用户可以进入水母漂浮的梦幻水族馆，安静地聆听音乐。

这些元素不是简单的背景装饰，而应该具有实际的交互意义。

Yohaku 应该像一间可以随身携带的私人阅览室，让用户在文字、音乐与回忆之间获得宁静。

## 二、设计美学

### 1. 整体艺术风格

设计灵感包括：

- 日式物哀美学（もののあわれ）
- 侘寂（Wabi-sabi）
- 日本夏日的怀旧气氛
- 35mm 胶片摄影
- 复古黑胶唱片和木质留声机
- 雨夜、夕阳、旧书、月光、玻璃风铃
- 萤火虫、水母、泡沫、樱花、烟花与蝉鸣

整体视觉应该精致、浪漫、克制，具有强烈的文学艺术气质。

强调真实的材质质感，例如磨砂玻璃、旧相纸、半透明胶片、木材、黄铜与和纸。

大量使用细腻的光影、自然的物理动画和精美字体。

**不要把软件设计成普通的 Material Design 工具，也不要堆砌花哨的动态壁纸。**

视觉效果应该服务于情感与交互，阅读舒适性始终优先。

## 三、核心空间设计

Yohaku 主要由三个彼此关联的空间构成。

### Space 1：暗室（Anshitsu）

**The Darkroom of Little Treasures**

这是软件的主界面，也是用户的私人书库。

书籍不再以传统网格书架呈现，而是变成一张张珍贵的老照片。

每一本书都是一张相纸，使用小木夹悬挂在暗房的细绳上。

#### 核心交互

1. 导入一本书时，出现柔和的相纸显影动画。
2. 书籍封面逐渐浮现在相纸上。
3. 用户可以将照片挂在暗房中的任意位置。
4. 照片会受到轻微的虚拟风力影响，缓缓摆动。
5. 点击照片，照片从绳子上浮起，逐渐展开为阅读界面。
6. 长按照片可以将其翻转，查看背面的收藏信息。

照片背面可以保存：

- 书籍名称与作者
- 收藏日期
- 阅读进度
- 用户的私人留言
- 最喜欢的一句话
- 曾经陪伴阅读的歌曲

允许用户自由整理、移动和收藏照片。

暗房里的书不必读完才能珍藏。尚未阅读的书也同样是用户的宝物。

**不要因为长时间不阅读就让照片消失或损坏。**

用户珍藏的书籍应该一直安静地等待他们回来。

### Space 2：留声机（The Gramophone Room）

**The Sound of Yesterday**

音乐收藏采用老式黑胶唱片与木质留声机的视觉设计。

这间房间可以与暗房自然连接，也可以是暗房中的一个独立音乐角落。

#### 音乐收藏

- 每张音乐专辑对应一张黑胶唱片及其唱片封套。
- 专辑封套展示真实的音乐专辑封面。
- 唱片柜用于管理本地音乐收藏。
- 用户可以自由整理唱片的位置和分类。
- 播放列表可以设计成独立的唱片收藏盒。

#### 播放交互

1. 用户从唱片柜中选择一张专辑。
2. 唱片从封套中缓缓取出。
3. 唱片被放到留声机的唱盘上。
4. 唱盘开始旋转，唱针轻轻落下。
5. 音乐开始播放。
6. 点击唱片或控制区域，可以查看曲目列表、播放进度和音量。

这些动作主要用于营造仪式感，必须支持跳过动画或直接播放。

播放器需要支持完整的数字音乐功能。

**黑胶唱片只是视觉隐喻，不能强制对 FLAC 等音乐施加失真、噪声或音质压缩。**

可提供独立关闭的唱片底噪选项，但默认保持原始音质。

### Space 3：海月（Kurage）

**The Aquarium of Dreams**

这是一个用于独立聆听音乐与放松的梦幻空间。

整体场景是一间幽暗、宁静的水族馆。

- 半透明水母在深蓝色水中缓慢漂浮。
- 微小气泡从底部升起。
- 光线穿过水面，产生柔和的折射。
- 用户可以轻触气泡，看到微弱的光晕。
- 音乐播放器以极简形式融入场景。

水母的触手与身体应具有自然、柔和的运动效果。

不需要让水母机械地跟随音乐节拍跳动。

场景应该像一个可以安静观察的数字艺术装置。

用户可以完全不阅读，只在这里播放音乐、环境声音或休息。

## 四、九种核心日式意象与交互

### 1. 樱花 · Sakura

樱花主要用于春季主题。

- 窗外偶尔飘过樱花。
- 用户收藏的句子可以成为樱花书签。
- 花瓣可以落在暗房的窗沿或木质桌面上。
- 动画必须克制，不能遮挡阅读正文。

### 2. 风铃 · Fūrin

玻璃风铃悬挂在暗房窗边。

- 微风吹过时轻轻摆动。
- 用户可以触碰风铃，让它发出清脆的声音。
- 风铃下方的短册可以写上收藏的诗句。
- 支持独立调整风铃音量或完全关闭。
- 不要让风铃过于频繁地响起。

### 3. 萤火虫 · Hotaru

萤火虫象征用户收藏的文字与记忆。

- 用户收藏喜欢的句子后，暗房中可以出现一只小小的萤火虫。
- 萤火虫缓慢漂浮，发出柔和微光。
- 轻触萤火虫，可以展开曾经收藏的文字。
- 萤火虫数量需要受到限制，防止视觉杂乱和性能下降。

### 4. 水母 · Kurage

水母是夜间聆听空间的核心元素。

- 采用半透明身体和柔软触手。
- 缓慢漂浮，具有自然的水下运动。
- 可以随环境光线改变透明度。
- 用户可以选择不同类型和颜色的水母。

### 5. 烟花 · Hanabi

烟花象征短暂的美与告别。

- 用户读完一本书后，可以自愿启动完读仪式。
- 远处夜空中缓慢绽放少量烟花。
- 烟花消散后，显示阅读完成日期及用户选择的一句话。
- 不提供频繁弹出的庆祝动画。
- 烟花音效必须可关闭。

### 6. 夕阳 · Yūyake

夕阳可以作为暗房的重要自然光源。

- 根据用户选择的时间或主题改变房间光线。
- 黄昏时，琥珀色阳光透过窗户照亮悬挂的照片。
- 夕阳逐渐消失后，暗房的暖色台灯亮起。
- 支持手动选择时间，不强制跟随系统时钟。

### 7. 雨 · Ame

雨是 Yohaku 最重要的环境意象之一。

- 雨滴沿窗户玻璃缓慢滑落。
- 背景中有柔和的雨夜光影。
- 用户可以选择细雨、中雨、屋檐雨等声音。
- 雨声可以独立播放，也可以与音乐混合。
- 雨滴不应影响正文显示和操作响应。

### 8. 伞 · Kasa

透明雨伞象征私人空间与庇护。

可以将伞设计为沉浸式阅读模式的入口：

- 用户点击伞的图标。
- 伞缓缓展开，背景逐渐变暗。
- 复杂的工具栏与装饰淡出。
- 屏幕只留下舒适、清晰的正文。
- 再次触碰即可退出沉浸模式。

### 9. 泡沫 · Awa

泡沫主要出现在水族馆与聆听空间。

- 微小气泡缓慢上升。
- 气泡具有透明、折射与微弱反光效果。
- 用户可以触摸气泡产生轻柔反馈。
- 泡沫不应该频繁遮挡音乐控制区域。

### 补充：蝉鸣与胶卷

蝉鸣是夏季主题的重要环境声音。

支持与风铃、微风、雨声进行独立音量混合。

胶卷则用于展示阅读记忆：

- 每次重要的阅读时刻可以保存为一格胶片。
- 胶片中记录书籍、日期、收藏的文字和当时播放的歌曲。
- 用户可以拖动胶卷，在不同年份的阅读记忆之间浏览。

注意：

**书籍收藏的主要视觉仍然是悬挂的相片，音乐收藏的主要视觉仍然是黑胶唱片。**

不要把所有内容都设计成胶卷。

## 五、阅读功能

支持以下格式：

- EPUB
- 无 DRM 的 AZW3
- PDF
- CBZ / ZIP 漫画
- TXT、Markdown 等常见文本格式

可以研究后续增加 CBR 支持。

### 文学阅读模式

- 高质量中英文排版
- 字体、字号、行距、页边距调整
- 章节目录、全文搜索、书签
- 高亮、批注和摘录
- 自动保存阅读进度
- 单页、双页及滚动阅读
- 暖纸、月白、墨夜等阅读主题

### 漫画阅读模式

- 支持日本漫画从右到左翻页
- 单页、双页、连续纵向滚动
- 双页跨页图像正确显示
- 图片缩放、拖动与适应屏幕
- 支持 Webtoon 式纵向长图阅读
- 自动保存漫画阅读位置

漫画全屏模式应隐藏风铃、樱花和其他动态装饰，保证作品画面完整。

### PDF 阅读模式

- 页面缩放与导航
- 目录和页面缩略图
- 文字选择与搜索（适用于含文字层的 PDF）
- 阅读进度保存
- 大文件与扫描 PDF 的性能优化

## 六、音乐播放器

支持本地音乐：

- FLAC
- MP3
- WAV
- AAC / M4A

实现：

- 音乐资料库扫描与导入
- 专辑封面与元数据读取
- 艺术家、专辑及歌曲管理
- 播放列表
- 后台播放
- Android 锁屏媒体控制
- 播放进度记忆
- 独立音量控制
- 无缝播放（条件允许时）
- 音频输出设备切换及耳机连接处理

播放过程中切换书籍、翻页、修改字体，不应造成音乐中断。

软件应当支持独立使用音乐播放器，不要求用户同时打开电子书。

## 七、环境声音系统

环境声音与本地音乐必须是相互独立的音频层。

支持：

- 雨声
- 海浪
- 微风
- 壁炉
- 森林
- 风铃
- 蝉鸣
- 夜晚虫鸣
- 水流与气泡声
- 可选的唱片底噪

允许用户同时播放多种声音，并独立调整音量。

提供：

- 平滑渐入渐出
- 睡眠定时器
- 自定义环境场景
- 环境声音预设保存
- 一键静音

可以设计几个默认场景：

| 场景 | 环境声音 |
|---|---|
| 雨夜暗房 | 屋檐雨声、微风 |
| 夏日午后 | 蝉鸣、风铃 |
| 海边黄昏 | 海浪、海风 |
| 深夜水族馆 | 水流、细小气泡声 |
| 冬夜书房 | 壁炉、窗外寒风 |

音乐与环境声音必须能够自由组合。

## 八、文学化交互与私人记忆

### 声音书签

用户收藏一段文字时，可以选择同时记录当前播放的歌曲及播放位置。

以后翻看书籍照片背面的记忆，可以重新播放那首音乐。

### 私人阅读场景

允许将以下内容保存为一个场景：

- 当前书籍
- 阅读位置
- 音乐或播放列表
- 环境声音组合
- 阅读主题
- 音量设置

例如「夏末的雨夜」「一个人的黄昏」「凌晨的水族馆」。

### 暗房记忆

允许用户收藏重要的阅读时刻，并通过胶卷形式回顾。

所有记录默认保存在本地。

不要加入阅读排行榜、强制签到、社交竞争等功能。

## 九、跨平台与技术要求

目标平台仅为：

1. Windows
2. Linux
3. macOS
4. Android

暂不开发 iOS。

优先研究 Tauri 2 + Next.js/React + Rust 的统一跨平台架构。

要求：

- 完全离线可用
- 不强制注册账户
- 用户数据本地保存
- 不修改原始书籍与音乐文件
- 保持阅读位置与收藏数据可靠
- 动态效果支持开关
- 支持低性能设备及减少动态效果模式
- 动画不应造成明显耗电或影响长时间阅读

桌面和移动端应采用适合各自设备的响应式交互。

不要简单地将桌面界面缩小后直接放在手机屏幕上。

## 十、开源项目参考

优先研究下列仓库：

### 1. Readest — 推荐作为阅读核心

https://github.com/readest/readest

- Tauri 2 + Next.js
- 支持目标四平台
- 支持 EPUB、AZW3、PDF、CBZ 等
- 已有完整的书籍管理与阅读功能
- 具有 GitHub Actions 发布流程
- 采用 AGPL-3.0 许可证

优先评估直接 Fork Readest 并改造的可行性。

### 2. Foliate-js — 阅读引擎

https://github.com/johnfactotum/foliate-js

- 支持 EPUB、AZW3 等格式
- 可作为独立阅读引擎
- MIT 许可证

如果决定不 Fork 完整的 Readest，可以考虑基于 Foliate-js 自行搭建阅读界面。

### 3. Koodo Reader — 备选阅读器

https://github.com/koodo-reader/koodo-reader

- 跨平台电子书管理与阅读
- 支持桌面和 Android
- AGPL-3.0 许可证

重点参考其书库管理与文件导入功能。

### 4. Harmonia — 音频架构参考

https://github.com/bgh30539-code/harmonia

- Rust + Tauri 2 + React + Rodio
- 支持 FLAC 等本地音乐
- 提供播放列表、无缝播放等音频功能
- MIT 许可证

目前不能直接将其作为完整的四平台解决方案，需要评估 macOS 与 Android 后台播放支持。

### 5. Rodio — Rust 音频播放库

https://github.com/RustAudio/rodio

研究用于 FLAC 解码、音频播放与多音源混合的可行性。

整合代码前必须检查许可证兼容性与第三方依赖。

## 十一、GitHub 云端编译

使用 GitHub Actions 构建：

- Windows：安装包及便携版本
- Linux：AppImage / DEB
- macOS：DMG
- Android：APK / AAB

发布版本使用 GitHub Releases。

Android 版本为未来 Google Play 等应用商店发布做好准备。

签名密钥必须安全管理，不得提交到代码仓库。

尽可能复用基础项目现有的 CI/CD 配置。

## 十二、开发顺序

请不要一开始同时实现所有艺术特效。

建议分阶段进行：

**Phase 1 — 阅读核心**

确定基础仓库，完成四平台构建，验证 EPUB、AZW3、PDF、漫画和进度保存功能。

**Phase 2 — 音乐与环境声音**

实现本地 FLAC 音乐播放、唱片库、Android 后台播放及独立白噪声混音。

**Phase 3 — Yohaku 暗房**

实现挂着书籍照片的暗房、照片显影、翻转和自由整理。

**Phase 4 — 留声机**

实现黑胶唱片收藏柜、唱盘、唱针及播放动画。

**Phase 5 — 日式艺术系统**

逐步加入雨、风铃、樱花、萤火虫、夕阳、伞、水母、泡沫、烟花、蝉鸣及四季主题。

**Phase 6 — 记忆与精修**

实现声音书签、胶卷记忆、私人阅读场景，并完成性能、可访问性和跨平台适配。

## 十三、重要设计原则

1. 所有日式元素都应具有合理的视觉或交互意义。
2. 不要让所有动画同时出现。
3. 不强制添加音乐音效或黑胶底噪。
4. 不为了动画破坏阅读和音乐播放体验。
5. 用户的书籍和唱片都是宝物，必须被可靠地保存。
6. 所有音效素材应自行制作或使用具有适当授权的资源。
7. 应为用户提供直接、简单的传统列表视图，不能强制依赖复杂动画操作。
8. 文学性来自整体体验，而非界面上堆砌诗句。

## 十四、最终愿景

Yohaku 应该是一间用户愿意长久停留的私人暗房。

墙上挂着珍爱的书，木柜里收藏着喜欢的黑胶唱片。

黄昏的阳光从窗户照进来。

玻璃风铃在微风中摇晃。

雨滴沿着窗户缓缓滑落。

一只萤火虫停留在某张书籍照片旁。

远处传来夏日的蝉鸣。

用户取下一本书，在留声机上放上一张唱片。

随着音乐响起，阅读开始。

**它不应该催促用户完成任何事情，只是温柔地收藏他们喜欢的一切。**

*Yohaku — A Quiet Place Between Words and Sound.*

## 执行要求（原文）

请先仔细阅读上述开源项目的架构、开发说明及许可证，尤其是 Readest 的跨平台构建方式。

第一步先完成技术可行性评估和项目改造计划，说明哪些功能可以复用、哪些需要新开发、哪些在 Android 上存在技术风险。

确认技术路线后再开始实现。

最终目标是一款真正可以长期使用、稳定运行、具有独特文学艺术气质的跨平台软件，而不是只有精美界面的演示作品。

本地只存代码和一些素材，所有测试、编译和发布都在 GitHub 上进行。仓库：https://github.com/Chaosnap/Yohaku
