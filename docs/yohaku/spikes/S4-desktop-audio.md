# Spike S4：桌面音频引擎

> 状态：原型完成，CI 离线渲染测试见 `ci.yml` 的 `spike-audio` 任务；真机部分（设备切换、长时间播放）待你在 Mac / Windows / Linux 上试听。
> 代码：[`spikes/s4-desktop-audio`](../../../spikes/s4-desktop-audio)（独立 crate，不进入应用的依赖图）。

## 要回答的问题

| 问题 | 通过标准（[路线图](../03-roadmap.md)） |
|---|---|
| 两曲之间是否有空白采样 | 离线渲染证明无缝 |
| 音量、静音、场景切换是否会有爆音 | 增益按采样平滑变化 |
| 睡眠定时是否按时淡出并暂停 | 精确到采样 |
| 44.1 kHz 音源在 48 kHz 设备上的重采样质量与 CPU 占用 | 可接受 |
| 拔出耳机或切换默认设备后能否继续 | 自动恢复 |

## 原型的结构

- **解码**：Symphonia 0.5（FLAC、WAV、MP3、AAC/M4A、ALAC、Ogg Vorbis），开启 `enable_gapless`，由解码器裁掉 MP3 / AAC 的编码器延迟与填充。
- **重采样**：Rubato 0.15 `SincFixedIn`（256 点 sinc、BlackmanHarris2 窗、三次插值），开头裁掉重采样器的延迟、结尾补零冲洗，使每首歌在输出采样率下的长度恰好是 `round(原长度 × 比率)`，下一首紧接着开始。
- **混音**：一个拉取式引擎，输出设备每次索取一块采样。音乐总线播放队列，当前曲目读完的同一块里就接上已预先打开的下一曲；环境总线上每个环境层各自循环（读到结尾即从头再读，同一块内衔接）；之后依次乘以音乐音量、环境总音量、主音量（静音）与睡眠定时增益。
- **渐变**：所有增益逐采样移动；音量与静音 20 ms 线性，场景切换为等功率（正弦 / 余弦）交叉渐变，睡眠定时线性淡出。
- **输出**：`output` 特性下用 cpal 打开默认设备；设备报告 `DeviceNotAvailable` 时丢弃旧的输出流，在新的默认设备上重建。

没有选 rodio：它的 `Sink` 能追加音源实现无缝，但每层的增益曲线、等功率交叉渐变与精确到采样的睡眠定时都需要自己控制采样，而直接拉取解码器与重采样器后，离线测试也更直接。最终方案在 Phase 2 确定。

## CI 中的测量

| 测试 | 断言 |
|---|---|
| 三段切开的立体声正弦（切点 23 457 与 51 233 帧，与 512 帧的输出块错开）排成队列 | 输出与原信号逐采样完全相等，队列结束后是静音，事件依次为换曲、换曲、队列结束 |
| 音量从 1 调到 0 | 882 帧（20 ms）内单调下降，每帧最多下降 1/882，之后为 0 |
| 静音与取消静音 | 20 ms 后分别为 0 与原音量 |
| 睡眠定时：500 ms 后用 250 ms 淡出 | 第 22 050 帧之前不变，之后 11 025 帧严格递减到 0，然后暂停并发出事件 |
| 两个环境层（各自的长度与音量）加音乐 | 混合结果在多次循环中保持恒定，音量互不影响 |
| 997 帧的环境层循环 | 5 000 帧内逐采样等于原样重复，没有接缝 |
| 场景从「雨」切到「海浪」，100 ms | 交叉渐变峰值为 √2 倍（等功率），结束后只剩新场景，旧环境层被移除 |
| 10 秒 1 kHz 正弦，44.1 kHz → 48 kHz | 长度恰好 480 000 帧；中间 8 秒按最小二乘拟合任意相位的 1 kHz 正弦，残差低于 −80 dB；由相位得到的输出滞后小于 10 帧；解码加重采样快于实时 20 倍 |

测量数值（误差 dB、滞后、实时倍数）在 CI 日志中打印。

首次运行的结果：解码加重采样约为实时的 117 倍；8 个测试中只有重采样一项未通过。原测试要求按整数帧对齐后偏移为 0，实际最佳对齐在 −5 帧，误差只有 −39.8 dB：裁掉 Rubato 报告的 `output_delay` 之后，输出仍比输入滞后约 5 帧（约 0.1 ms），而且含有小数帧的残余，整数帧对齐无法消除。测试因此改为拟合任意相位的正弦，分别检查失真与滞后。这个滞后听不出来，也不影响每首歌的长度与两曲之间的无缝衔接；Phase 2 的正式引擎会用脉冲实测重采样器的真实延迟再裁剪。

## 待真机验证

- 用 `cargo run --release --features output --example play -- a.flac b.flac --rain rain.ogg` 试听无缝衔接与环境层；
- 播放中拔出耳机、切换默认输出设备，确认几百毫秒内在新设备上继续；
- 长时间（≥ 2 小时）播放的稳定性与 CPU 占用。

## 结论（暂定）

Symphonia + Rubato + cpal 的自写管线可以满足无缝、渐变与睡眠定时的要求，并且可以完全离线测试。Phase 2 在此基础上加入：独立的引擎线程与无锁环形缓冲（不在音频回调中解码）、多声道的正确缩混、按曲目的预读时机（剩余约 10 秒时打开下一曲）、souvlaki 媒体会话。
